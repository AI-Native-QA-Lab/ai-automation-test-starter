# Contributing

## Contribution Philosophy

Contributions should make test automation easier to learn without
weakening engineering quality.

English is the canonical language for public project contracts. Chinese
localizations live under `docs/zh-CN/`; development process notes may be
written in Chinese, but localized behavior must stay aligned with the
English contract.

## Before Starting

For significant changes:

1.  open an issue;
2.  identify affected contract;
3.  discuss architecture if adapter/core boundary changes;
4.  write or update tests first.

## Local Validation

Expected commands will be finalized during repository bootstrap. The
baseline should include:

``` bash
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm test:contract
pnpm test:e2e
```

Framework adapter tests may require their native runtime.

## Pull Request Requirements

A PR should include:

-   problem;
-   approach;
-   tests;
-   evidence;
-   documentation impact;
-   compatibility impact;
-   screenshots only when UI exists.

## Adapter Contributions

A new adapter must:

-   solve a demonstrated use case;
-   remain framework-native;
-   pass adapter conformance;
-   include a runnable starter;
-   include beginner learning material;
-   include quality rules;
-   identify native evidence/report behavior.

## AI-generated Contributions

AI-generated code is welcome, but the contributor remains responsible
for:

-   correctness;
-   licensing;
-   tests;
-   security;
-   maintainability;
-   documentation.

"Generated by AI" is not verification.
