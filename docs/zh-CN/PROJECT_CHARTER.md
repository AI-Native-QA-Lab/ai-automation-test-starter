# 项目章程

> [English（规范文档）](../product/PROJECT_CHARTER.md) · 简体中文

## 使命

让现代测试自动化更容易学习，也让使用 AI 构建自动化测试更安全。

## 目标用户

- 开始学习自动化的 QA 工程师；
- 从手工测试转向自动化的测试人员；
- 初级自动化工程师；
- 正在学习测试框架的开发者；
- 负责搭建自动化框架的高级 QA、团队和培训者。

## 项目要解决的问题

项目帮助用户选择合适的测试路径，理解框架原生概念，构建第一个有意义的自动化测试，诊断失败，判断 AI 生成测试是否可信，并逐步从教练式学习走向辅助工程。

## 产品原则

### 面向初学者，但不只服务初学者

入门体验应当易于理解，生成的项目和工程实践仍应面向真实生产场景。

### 框架原生

不发明统一的断言、运行器、页面对象、HTTP 客户端或负载模型 API。用户直接学习 Pytest、Playwright、k6 等框架。

### AI 输出必须经过质量门禁

AI 输出只是提案，必须经过仓库规则、可执行检查和质量审查后才能作为工程结果。

### 渐进式自治

自治能力按 `Explain → Coach → Assist → Build → Agent` 逐步获得。MVP 先交付 Learn/Build，Agent Mode 后置。

### 证据优先于自信

系统区分模型建议、静态校验、可执行测试结果、CI 结果和人工批准。

## 非目标

本项目不是 Pytest、Playwright、k6 或其他框架的替代品，不是托管测试管理系统，不是通用 QA 运行器，也不是在没有执行和审查的情况下保证生成测试正确的工具。

## 当前成功标准

初学者应能够完成：

```text
初始化项目 → 理解目标 → 创建有意义的测试 → 运行 → 理解失败 → 修复 → 审查质量 → 接入 CI
```

且项目不会隐藏底层测试框架。
